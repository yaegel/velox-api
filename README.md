# VeloxAPI

A lightweight, database-backed task queue and dashboard monitoring system built for Flask web applications.

## Key Features

- **Database-Backed Queue**: Tasks are safely written to a PostgreSQL table and processed by background worker threads.
- **Flask Integration**: Easily expose functions as asynchronous HTTP endpoints.
- **Embedded Web Dashboard**: View and monitor task statistics, processing states, parameters, execution trace logs, and download zip files of execution archives.
- **Clipboard Integration**: Fast copy buttons for parameters, results, and debug errors.

## Installation

To install in your project environment:
```bash
pip install -e /path/to/velox
```

## Quick Start

```python
from flask import Flask
from velox import VeloxAPI

app = Flask(__name__)

# Initialize VeloxAPI
velox_api = VeloxAPI(
    schema="my_service",
    host="localhost",
    port=5432,
    user="postgres",
    password="password",
    dbname="services_db"
)

# Register endpoints as async tasks
@velox_api.async_task(priority=1, route='/calc/version')
def calc_version(**kwargs):
    return {"version": "1.0.0"}

# Register the blueprint with Flask
app.register_blueprint(velox_api.blueprint)

if __name__ == '__main__':
    # Start worker threads
    velox_api.start_workers(num_threads=2)
    # Start web server
    app.run(port=5000)
```

## Automatically Available Endpoints

When you register the `velox_api.blueprint` on your Flask application, several endpoints are automatically exposed. Note that if you register the blueprint with a prefix (e.g., `app.register_blueprint(velox_api.blueprint, url_prefix='/velox')`), these paths will be prefixed accordingly.

### 1. Dynamic Task Endpoints
Each function decorated with `@velox_api.async_task` is automatically exposed as an HTTP endpoint.
* **Route**: `/{task_name}` (defaults to the python function name, or a custom `route` if provided to the decorator).
* **Methods**: `POST` by default (or custom HTTP methods if specified).
* **Arguments**: Request JSON body fields (for non-GET methods) and URL query parameters are automatically merged and passed as keyword arguments (`**kwargs`) to the registered function.
* **Execution Modes**:
  * **Asynchronous (Default)**: Queues the task in the database and returns a `202 Accepted` response immediately with a task receipt:
    ```json
    {
      "message": "Task 'calc_version' successfully received and queued.",
      "receipt": {
        "status": "queued",
        "task_id": "8f8c7b8d-abcd-71ef-8abc-1234567890ab"
      }
    }
    ```
  * **Synchronous**: If a `sync=true` parameter is supplied in the query string or the JSON body (or `sync=True` is set in the decorator), the task executes synchronously on the request thread.
    * **Success**: Returns `200 OK` with the JSON-serialized return value of the function.
    * **Failure**: Returns `500 Internal Server Error` containing the exception details and the task ID:
      ```json
      {
        "error": "Error description...",
        "task_id": "8f8c7b8d-abcd-71ef-8abc-1234567890ab"
      }
      ```

### 2. Embedded Web Dashboard
* **Route**: `/dashboard`
* **Method**: `GET`
* **Query Parameters**:
  * `status`: Optional filter by task status (`all`, `queued`, `processing`, `completed`, `failed`). Defaults to `all`.
* **Description**: Renders a built-in monitoring user interface that lists task executions, their statuses, priorities, timestamps, and details.

### 3. Task Diagnostics APIs
The following endpoints are used by the dashboard to fetch execution details and can also be queried programmatically:

* **Get Task Arguments**:
  * **Route**: `/dashboard/<task_id>/args`
  * **Method**: `GET`
  * **Description**: Returns the JSON input arguments passed to the task.

* **Get Task Result**:
  * **Route**: `/dashboard/<task_id>/result`
  * **Method**: `GET`
  * **Description**: Returns the JSON result payload generated by the task (if completed successfully).

* **Get Task Error**:
  * **Route**: `/dashboard/<task_id>/error`
  * **Method**: `GET`
  * **Description**: Returns the recorded exception traceback if the task execution failed.

* **Get Task Logs**:
  * **Route**: `/dashboard/<task_id>/logs`
  * **Method**: `GET`
  * **Description**: Returns the captured standard logging output emitted during the execution of the task.

* **Download Task Archive**:
  * **Route**: `/dashboard/<task_id>/archive`
  * **Method**: `GET`
  * **Description**: Bundles the task's input payload (`payload.json`), result (`result.json`), recorded exceptions (`error.log`), and execution logs (`task.log`) into a single `.zip` file for download.
